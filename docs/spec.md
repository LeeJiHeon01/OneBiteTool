## 0. 용어 사전

| 용어 | 의미 |
| --- | --- |
| 제공 레시피 | COOKRCP01 등에서 가져와 DB에 정리한 레시피 |
| 웹 검색 레시피 | 제공 레시피에 없는 요리를 GPT 웹 검색으로 **실제 웹페이지에서 찾아** 구조화한 레시피. 출처 URL 있음, 앱 검증 전 |
| 외부 레시피 | 사용자가 붙여넣은 레시피 글 (MVP 이후) |
| 재구성(Adaptation) | 레시피 + 사용자 조건 → 맞춤 안내 |
| 도구 선택지(ToolVariant) | 사용자가 고르는 아이콘 하나 (예: 종이컵, 가위, 전자레인지) |
| 대표 용량 | 선택지별로 앱이 정한 기준 용량. **실측값 아님** |
| 담기 기준(FillLevel) | "깎아서", "소복이" 등 검증된 담는 방법과 그 그림 |
| 민감 재료 | 간을 정하는 재료. 오차를 엄격히 다룬다 |
| 검증 | 사람이 직접 확인한 것. GPT 결과는 검증이 아님 |

## 1. 제품 목표

**핵심 가설:** 초보자(특히 도구가 부족한 자취생)가 기존 레시피보다 덜 막히고 끝까지 따라 할 수 있다.
**목적:** 포트폴리오 완성이 1순위, 출시는 2순위 [확정]. 범위는 §12의 1차/2차로 나눈다.
**비목표:** 요리 동기 부여, 사용자 임의 재료 추가, 정확한 실측 계량 보장.

- 재방문 사용자는 로그인 후 S3부터 시작한다. 설정 화면에서 실력·도구·알레르기를 수정한다. [가정]
- DB에 없는 요리는 웹 검색으로 가져온다 (§6.3).
- S3(b)에서 입력한 재료는 **추천용**이다. S5에서는 [가정] 입력하지 않은 재료를 '없음'으로 미리 체크해 둔다. S5에서 새 재료를 추가하는 기능은 여전히 없다.

### 2.3 둘러보기(게스트) [확정: 1회 체험]
- 첫 화면에서 '둘러보기'를 고르면 가입 없이 **요리 1회**를 끝까지 체험할 수 있다(S1~S7).
- '1회'의 기준 [가정]: 재구성 결과(S6)를 1번 받는 것. 같은 결과를 다시 여는 것은 횟수에 포함하지 않는다.
- 1회를 쓴 뒤 새 요리를 시작하면 가입 화면으로 안내한다.
- 횟수는 서버가 기기 식별값으로 센다. 앱 재설치 등으로 우회될 수 있지만 MVP에서는 허용한다. [가정]
- 실력·도구는 기기에만 임시 저장하고, 가입하면 프로필로 옮긴다.
- [확정 2026-10-09] 1차의 기기 저장: 실력·도구·알레르기·동의 여부를 기기의 암호화 저장소(`expo-secure-store`: iOS 키체인 / Android 키스토어)에 둔다. 앱을 다시 켜면 불러오고, 처음 설정을 마친 사용자는 홈 화면에서 시작한다. 설정의 '모두 삭제'는 저장된 값도 비운다. 웹 미리보기(개발용)는 암호화 저장소가 없어 알레르기를 저장하지 않는다.
- 게스트도 알레르기를 입력할 수 있다. 서버에는 요청할 때만 보내고 저장하지 않는다.

### 2.4 가입 규칙 [확정]
| 항목 | 규칙 |
| --- | --- |
| 아이디 | 영문 소문자·숫자, 4~20자, 중복 불가. 로그인에 사용 |
| 비밀번호 | 영문과 숫자를 모두 포함, 8자 이상. BCrypt 해시 저장 |
| 닉네임 | 중복 불가. 길이 2~12자, 한글·영문·숫자 [가정] |
| 이메일 | 형식 검사, 중복 불가. 아이디 찾기·비밀번호 찾기에 사용 |

- 아이디 찾기: 이메일 입력 → 해당 이메일로 아이디 안내 메일 발송. 화면에는 가입 여부를 드러내지 않는 같은 문구를 보여준다 [가정].
- 비밀번호 찾기: 아이디+이메일 확인 → 재설정 링크 메일(1회용, 만료 있음).
- 이메일 소유 인증(가입 시 인증 메일)은 1차에서 생략하고 출시 전 추가 [가정].

### 2.1 실력별 설명 수준 [확정]

| 값 | 표시 이름 | 안내 범위 |
| --- | --- | --- |
| `LOW` | 처음 해봐요 | 담는 방법, 도구 사용법, 불 조절, 조리 상태까지 |
| `MID` | 기본 요리는 해요 | 계량과 주요 조리 과정 중심 |
| `HIGH` | 요리에 익숙해요 | 핵심 과정과 변경 사항만 |

변하지 않는 것: 단계 수·순서, 시간, 불 세기, 상태 확인, 계량값, **안전 주의사항**.
무게(g)로 적힌 재료는 실력에 따라 표현만 달라진다: `LOW`는 도구 기준 + 괄호 안 g, `MID`·`HIGH`는 g 그대로(§4.7).

### 2.2 없는 재료 처리 [확정]

| 값 | 동작 |
| --- | --- |
| `OMIT` | 생략 사실과 영향 안내 |
| `SUBSTITUTE` | 검증된 대체안 제시 → 보유 여부 확인 → 없으면 다음 대체안 또는 `REQUIRED` |
| `REQUIRED` | 조리 불가, 이유 안내 |

규칙이 없는 재료가 없으면 `REQUIRED`로 처리한다. [가정, 보수적]

## 3. 도구 [확정 + 일부 가정]

### 3.1 분류

| 분류 | 예시 선택지 | 용량값 | 비고 |
| --- | --- | --- | --- |
| 계량 | **계량스푼, 계량컵**, 밥숟가락, 티스푼, 종이컵(자판기 컵), 유리컵, 생수병(500mL), 밥공기, *큰 종이컵, 국그릇, 쌀컵, 소주잔* | 있음(표준 계량 도구는 없음) | 계량스푼·계량컵은 "표준 계량 도구" 항목 |
| 자르기 | 칼, 가위, 필러(감자칼), 채칼, 강판 | 없음 | 도마는 선택 항목에서 제외 [확정] |
| 가열 기기 | 가스레인지, 인덕션, 전자레인지, 에어프라이어, 전기밥솥, 오븐(광파오븐 포함) | 없음 | 여러 개 선택 가능. 화구 없이 전자레인지만 있는 경우도 지원 |
| 조리 용기 | 냄비, 프라이팬, 전자레인지용 용기, 찜기, 뚝배기 | 없음 | 밥공기·국그릇은 섞기·풀기 용기 역할도 한다 |

표의 순서가 화면 표시 순서(`sort_order`)다. *기울임* 표시는 '더 있어요' 안에 들어가는 도구(`is_basic = false`)다. [확정 2026-10-09]
`paper_cup_small`의 표시 이름은 '종이컵'이다(이전 이름: 작은 종이컵).

- 기존의 `stoveType`은 가열 기기 선택으로 흡수한다. 불 세기 그림은 가스/인덕션 중 사용자가 가진 것으로 표시하고, 둘 다 있으면 [가정] 사용자가 기본값을 고른다.
- [확정] 냄비 뚜껑, 국자, 체, 집게, 거품기는 선택 항목에서 제외한다. 이 도구들은 있다고 가정하지 않는다. 레시피에 나오면 단계 안내에 대안(예: 체 대신 숟가락으로 건지기)을 넣거나 '있으면 편해요'로만 표시한다 [가정].
- 도마는 확인하지 않는다. [가정] 칼이 있으면 자를 수 있다고 본다.

### 표준 계량 도구 [확정]
- 계량스푼 또는 계량컵을 가진 사용자에게는 **원래 레시피 단위(큰술·작은술·컵·mL)를 그대로** 보여준다. 변환하지 않으므로 '대략적인 기준' 배지도 붙이지 않는다.
- 둘 중 하나만 있으면 그 도구가 담당하는 단위만 원래대로 보여준다(계량스푼 → 큰술·작은술, 계량컵 → 컵·mL). 나머지는 기존 변환 규칙을 따른다.
- 도구 선택 화면 맨 위에서 "계량스푼·계량컵이 있나요?"를 먼저 묻는다 [가정].

### 도구 선택 화면 구성 [확정]
- 분류마다 앞의 6개까지는 바로 보이고(`is_basic = true`), 7번째부터는 그 분류 아래 '더 있어요'를 눌러 펼친다. 표준 계량 도구(계량스푼·계량컵)는 맨 위에서 따로 묻기 때문에 개수에 넣지 않는다.
- '요리에 익숙해요'를 고른 사용자는 '더 있어요'를 처음부터 펼친 상태로 보여준다 [가정].
- 그릇(밥공기·국그릇)과 생수병은 옆면이 둥글거나 병 모양이라 눈금을 계산하지 않는다. "가득 1번", "반 정도"처럼 글자로만 안내하고, 액체를 잴 때는 종이컵·생수병을 그릇보다 우선 추천한다.

### 3.2 도구 대체·조리법 변경
레시피가 요구하는 도구가 없을 때:
- 검증된 `ToolSubstitutionRule`이 있으면 적용한다. 예: 칼→가위 (부드러운 재료만), 프라이팬→냄비.
- 가열 방식 변경(가스→전자레인지 등)은 **조리법 변경**이다. 시간·안전 기준이 달라지므로 레시피별로 검증된 규칙이 있을 때만 적용한다.
- 규칙이 없으면 `requiredItems`에 도구를 넣는다.

## 4. 계량 규칙

### 4.1 COOKRCP01 데이터 특성 (확인 완료)
- 인분 필드는 **없다**. 대신 `INFO_WGT`가 "중량(1인분)"이고, 열량·나트륨 등 영양 정보도 1인분 기준이다.
- 재료정보(`RCP_PARTS_DTLS`)는 하나의 문자열이다. 예: `설탕 2g(1/3작은술), 물 200ml(1컵), 고구마 100g(2/3개)` → **g 옆 괄호에 숟가락·개수 환산이 들어 있는 경우가 많다.**
- 재료 사이에 소제목(예: "채소준비", "양념장")이 섞여 있어 파싱이 필요하다.
- 이 API는 1컵을 200ml로 쓴다.
- 조리 순서는 `MANUAL01~20`이다. 끝에 붙은 a/b/c 같은 잡문자를 제거해야 한다. 단계 이미지는 일부만 있다.
- 호출 제한은 1000이다(기간 단위는 확인 필요). 한 번에 최대 1000건을 받을 수 있다. 메뉴명·재료로 검색할 수 있다.
- 이용 허락 범위와 상업적 이용 가능 여부는 정보 페이지에 나와 있지 않다. 출시 전에 확인한다.

### 4.2 변환 파이프라인 (서버 코드)

```
재료 문자열 → 파싱(이름, 수량, 단위, 괄호 환산, 원문, 소제목)
  ├─ 괄호에 큰술/작은술/컵 있음 → 그 값을 mL로 환산(1큰술 15, 1작은술 5, 1컵 200 [가정])
  │                             → 사용자 도구의 검증된 담기 기준으로 표현
  ├─ 부피 단위(ml, 큰술 등)      → 위와 동일
  ├─ 괄호에 개수 있음(2/3개, 1쪽) → 개수 표현 사용, 도구 변환 없음
  ├─ g만 있음(고기 100g 등)       → 실력 MID/HIGH: g 그대로(ORIGINAL)
  │                                 실력 LOW: 재료별 무게 기준(§4.7)이 있으면 도구 표현 + (g) → CONVERTED_APPROX, 없으면 g + NEEDS_CHECK
  └─ 약간·적당량                  → NEEDS_CHECK (민감 재료면 "맛보며 조금씩")
```

### 4.3 민감도와 오차 [가정, 사용자 검토 필요]

| sensitivity | 예 | 규칙 |
| --- | --- | --- |
| `HIGH` | 소금, 간장, 액젓, 된장, 고추장, 설탕, 고춧가루 | 원문보다 많아지게 반올림하지 않는다. 남는 양은 "맛보고 추가"로 안내 |
| `RATIO` | 밀가루, 부침가루, 튀김가루, 전분, 쌀 | 비율이 중요한 재료. 가장 가까운 양으로 안내하되 허용 오차 **10%**. 넘으면 변환하지 않고 원문 + `NEEDS_CHECK` |
| `NORMAL` | 물, 식용유, 참기름 | 가장 가까운 검증된 담기 기준으로 반올림. 허용 오차 **25%** |

예: 원문 1.3숟가락 → `HIGH`면 "1숟가락 넣고 맛본 뒤 더하기", `NORMAL`이면 "1숟가락".

[확정 2026-10-09, 결정 D-6] 민감도는 3단계다. 값은 재료 사전(`data/seed/ingredients.json`)에 있고, 허용 오차는 `data/seed/units.json`의 `normalToleranceRatio`(0.25)·`ratioToleranceRatio`(0.10)다.
- **물의 문맥 규칙**: 물은 `NORMAL`이지만, 같은 단계에 `RATIO` 재료(쌀·밀가루·전분 등)가 함께 쓰이면 그 물도 `RATIO`로 다룬다(밥물, 반죽 물). 찜처럼 함께 쓰는 `RATIO` 재료가 없는 경우는 아직 다루지 못한다 [미정].
- **분류와 형태는 다르다**: `category`는 분류 이름(양념, 채소, 기름 …)이고, 계량에 쓰는 형태는 `form`(`LIQUID`/`POWDER`/`PASTE`/`SOLID`)이 정한다. 같은 '양념' 안에 간장(액체)·소금(가루)·된장(걸쭉한 양념)이 섞여 있기 때문이다. 사전에 없는 재료는 `SOLID`·`HIGH`로 다룬다.
- 2026-10-09 분류 자료로 재료 126개의 `category`·`sensitivity`를 채웠다. `form`은 그 자료에 없어 이전 동작을 유지했다: 새로 들어온 재료는 기름만 `LIQUID`이고, 식초·맛술·청주·꿀 같은 액체도 아직 `SOLID`다(숟가락 단위는 변환되고, ml·컵은 컵으로 바꾸지 않는다) [미정: 형태 지정 필요].

### 4.4 대표 용량 값 확보 [확정: 직접 측정 불가]
개발자가 직접 측정할 수 없으므로 모든 기준값에 **출처 등급**을 붙인다.

| `valueSource` | 의미 | 화면 안내 |
| --- | --- | --- |
| `MEASURED` | 주변 도움 등으로 실제 측정 | "약 N숟가락" |
| `PUBLISHED` | 공신력 있는 자료(공공기관·학술 자료)에서 인용, 출처 기록 | "약 N숟가락" |
| `ASSUMED` | 근거 없이 정한 임시값 | "약 N숟가락 (대략적인 기준이에요)" + 민감 재료는 반드시 맛보기 안내 |

- 개발 초기에는 `ASSUMED` 임시값으로 진행하고, 값은 `data/seed/tools.json` 한 곳에서만 관리한다(나중에 교체 쉬움).
- 계량스푼 표준값(1큰술 15mL, 1작은술 5mL)과 COOKRCP01의 1컵=200mL는 원문 단위 해석에 쓰는 기준이며, 밥숟가락·종이컵의 실제 용량과는 별개다.
- 출시 전까지 `ASSUMED` 값을 바꾼다. [확정] 방법: **1순위 자료 검색**(`PUBLISHED`, 출처 URL·확인일 기록. 공공기관·학술 자료 우선, 블로그 단독 출처는 쓰지 않음 [가정]), 2순위 주변 도움 측정(`MEASURED`). 검색으로 못 찾은 항목만 `data/seed/MEASURE_GUIDE.md` 체크리스트로 측정을 부탁한다.
- [변경 2026-10-09] 분수(반 숟가락 등)는 `ASSUMED` 상태에서도 쓴다. 가진 도구로 표현하려면 필요하기 때문이다(§4.7). 대신 변환된 양은 항상 '대략적인 기준'으로 표시한다. 담기 기준 **그림**은 실제 측정과 대조해 검증한 것만 쓰고, 그림이 없으면 글자로만 안내한다.
- 간 재료(`HIGH`)는 '적게 넣고 맛보며 추가' 규칙 덕분에 임시값이 틀려도 짜게 망칠 위험이 줄어든다.

### 4.5 인분 [확정 + 가정]
- 1인분 레시피를 우선 사용한다. COOKRCP01은 `INFO_WGT` 기준으로 1인분 데이터로 간주하되, 레시피별로 사람이 확인한다.
- 1인분이 없으면 2인분을 줄인다. 다만 반으로 줄이는 것은 단순 계산이 아니다.
  - 개수: 달걀 1개 → 0.5개는 불가 → 규칙 필요
  - 물: 증발량 때문에 정확히 반이 아닐 수 있음
  - 시간: 대부분 줄지 않음
  - 그래서 레시피별로 검증된 경우만 적용한다. [가정]

### 4.6 무게만 있는 재료의 비교 기준 [방향 확정, 값은 측정 필요]
저울이 없는 사용자를 위한 기준. 손 비교는 오차가 커서 **사용하지 않는다** [확정].
1. **개수·단위**: 원문 괄호에 개수가 있으면(`고구마 100g(2/3개)`) 그대로 쓴다. 없으면 `WeightReference`(출처 등급 포함)가 있을 때만 개수로 바꾼다.
2. **포장 기준 질문하기** [확정]: 고기처럼 개수가 없는 재료는 g 원문을 보여주고 "가진 포장 기준으로 알려드릴까요?" 버튼을 둔다 → §6.7 재료 질문하기로 연결.
3. 둘 다 없으면 g 원문 + `NEEDS_CHECK`.

`WeightReference`: ingredient, unitLabel(1개/1모), approxGrams, sizeNote(중간 크기), valueSource, sourceRef.

### 4.7 도구로 양을 표현하는 규칙 [확정 2026-10-09]
사용자가 **고른 도구**만 써서 표현한다. 계산은 서버 코드가 한다.

**0) 표준 계량 도구가 먼저다**
계량스푼을 가진 사용자의 큰술·작은술, 계량컵을 가진 사용자의 컵·mL는 변환하지 않고 원문 그대로 보여준다("표준 계량 도구" 항목). 아래 규칙은 그 도구가 없을 때 적용한다.

**1) 숟가락 단위는 제 숟가락부터**
| 원문 단위 | 먼저 쓰는 도구 | 그 도구가 없으면 |
| --- | --- | --- |
| 큰술 | 밥숟가락 | 티스푼으로 환산 |
| 작은술 | 티스푼 | 밥숟가락으로 환산 (예: 1작은술 → "밥숟가락 반") |

오차가 더 작다는 이유로 다른 숟가락으로 넘어가지 않는다(1큰술을 "티스푼 3번"으로 안내하지 않는다).

**2) 분수를 쓴다**
- 숟가락: `fill_level` 테이블에 있는 양만 쓴다(밥숟가락 1/3·1/2·2/3·가득, 티스푼 1/2·가득). 소복이는 용량을 알 수 없어 계산에 쓰지 않는다.
- 컵(치수가 있는 종이컵·유리컵): 1/3·1/2·2/3. 눈금 위치는 치수로 계산해서 그린다(높이의 절반이 용량의 절반이 아니다). AI로 만든 그림은 쓰지 않는다.
- 그릇·병(밥공기·국그릇·생수병·쌀컵·소주잔): 눈금을 계산하지 않는다. "가득"과 "반 정도"만 쓴다.
- 표현: 가득 횟수 + 분수 하나. "밥숟가락으로 1번 반", "밥숟가락 반", "종이컵 2컵", "종이컵 반 컵", "밥공기로 가득 1번", "밥공기 반 정도".
- 그림이 아직 없는 분수(manifest의 `missing`)는 글자로 안내하고 그림 자리는 비워 둔다.

**3) 부피(ml·컵)는 액체만 컵으로**
- 액체(물·육수·간장·기름 등)의 ml·컵: 컵 → 생수병 → 그릇(밥공기·국그릇) → 숟가락 순으로 고른다(순서는 `data/seed/units.json`의 `volumeTools`). 30mL 미만은 숟가락부터. 예: 물 400ml → "종이컵 2컵".
- 같은 종류 안에서는 분수 없이 떨어지는 표현을 먼저 고른다.
- **고체는 컵·그릇의 부피로 바꾸지 않는다.** 원문에 "김치 1컵"처럼 적혀 있으면 원문 그대로 보여준다.
- 재료의 형태(액체/가루/걸쭉한 양념/고체)는 재료 사전의 분류로 정한다. 사전에 없는 재료는 고체로 본다.

**4) 밥공기·국그릇**
- 냄비·프라이팬은 크기가 제각각이라 "냄비 반쯤" 같은 안내를 하지 않는다. 큰 양은 밥공기·국그릇 횟수로 안내한다.
- 밥공기(300mL)·국그릇(500mL)은 도구 선택 항목이다. 용량은 [가정, `ASSUMED`]이고 제품 편차가 커서 항상 '대략적인 기준'으로 표시한다.
- 그릇은 "가득"과 "반 정도"만 쓰므로 그 사이의 양(예: 밥공기 3/4)은 변환하지 않고 원문 + `NEEDS_CHECK`로 둔다.

**5) 무게(g)는 실력에 따라 보여주는 방식이 다르다**
| 실력 | 표시 |
| --- | --- |
| 처음 해봐요(`LOW`) | 도구 기준 + 괄호 안에 g. 예: "밥공기로 가득 1번 (200g)" |
| 기본 요리는 해요 / 요리에 익숙해요 | g 그대로. 예: "150g" |

- g를 도구로 바꾸려면 **재료별 무게 기준**이 필요하다("김치는 밥공기 1번에 약 200g", `weight_reference` 테이블, `data/seed/weight-references.json`). g와 mL는 재료마다 달라 계산으로 구할 수 없다.
- 기준이 없는 재료나 기준 도구를 갖지 않은 사용자에게는 g만 보여주고 `NEEDS_CHECK`로 표시한다. 숟가락·컵으로 어림하지 않는다.
- 지금 기준값은 모두 `ASSUMED`다. AI 검색으로 채울 때도 사람이 확인한 뒤 `PUBLISHED`/`MEASURED`로 바꾼다.
- 양 자체는 실력과 상관없이 같다. 달라지는 것은 표현뿐이다.

**6) 눈대중 표현을 쓰지 않는다**
- 우리가 쓰는 레시피(고정 레시피)에는 "약간", "한 줌", "적당량"을 쓰지 않고 구체적인 양을 적는다.
- 웹에서 가져온 레시피에 "약간"이 있으면 숫자를 지어내지 않고 `NEEDS_CHECK`로 둔다(§4.2).

**7) 간 재료와 오차**
- 간 재료(`HIGH`)는 원문보다 많아지지 않게 내림한 양으로 안내하고 "맛보고 추가"를 붙인다. 예: 1.9숟가락 → "1번과 2/3".
- 그 밖의 재료는 가장 가까운 양으로 안내하되 오차가 허용 범위(임시 25%, Q-D1)를 넘으면 변환하지 않고 원문 + `NEEDS_CHECK`로 둔다.
- 변환된 양은 모두 근사값이므로 '대략적인 기준'으로 표시한다.
- 컵의 대표 용량은 "가득 기준선"(입구에서 `fillLineFromTopMm` 아래)까지이며, 치수 계산값과 5% 넘게 다르면 서버가 시작하지 않는다.

## 5. 안전·알레르기 [확정 방향, 데이터는 작업 필요]

### 5.1 안전 주의사항
- `SafetyRule`(사람이 작성·검증): 트리거(재료/행동/도구) → 표시 문구 → 표시 위치(해당 단계, 조리 전 요약)
  - 예: 돼지고기·닭고기 → 속까지 완전히 익히기 + 확인 방법 / 뜨거운 기름 → 물기 제거, 튐 주의 / 전자레인지 → 금속 용기 금지 / 칼·가위 사용 단계
  - 도구 추가로 필요한 규칙(1차에 작성·검증 필수):
    - 채칼·강판 → "손 보호대를 쓰고, 재료가 짧아지면 끝까지 밀지 마세요"
    - 오븐 → "오븐 장갑을 끼고, 문을 열 때 얼굴을 떼세요" / 예열 중 내부 접촉 금지
    - 찜기 → "뚜껑을 열 때 김에 데지 않게 몸 쪽 반대로 여세요"
    - 뚝배기 → "불에서 내린 뒤에도 오래 뜨거워요. 맨손으로 잡지 마세요"
    - 에어프라이어 → "바스켓을 꺼낼 때 손잡이만 잡으세요"
- 모든 실력 수준에서 표시한다. `LOW`는 이유와 확인 방법까지 함께 보여준다.
- GPT는 문구를 다듬을 수만 있다. 규칙에 없는 안전 판단은 하지 않는다.

### 5.2 알레르기
- 가입 시 입력하고 프로필에 저장한다. 목록은 식약처 알레르기 유발물질 표시 대상 기준으로 한다 [가정, 최신 목록 확인 필요].
- `AllergenMapping`: 재료 → 알레르기 항목. 숨은 성분을 포함한다(간장→대두·밀, 고추장→밀, 마요네즈→알류 등).
- 레시피 목록에서는 해당 알레르기가 있는 레시피를 기본 제외한다.
- 결과가 해당 레시피뿐이거나 사용자가 직접 연 경우에는 조리 전에 경고 화면을 보여준다(확인해야 진행).
- 매핑에 없는 재료는 "알레르기 확인 필요"로 표시한다.
- [변경 2026-10-09: 아래 "매핑 검토 등급"이 이 항목을 대체한다. 1차에서는 `AI_RESEARCHED`도 확인된 매핑으로 쓴다.] ~~사람이 검증한 재료만 "확인됨"으로 본다.~~ `data/seed/allergen-mapping.json`에서 `verifiedBy`(확인한 사람)와 `verifiedAt`이 채워진 재료만 해당한다. 사전에 없거나, 매핑이 없거나, `verifiedBy`가 비었거나 `DRAFT_UNVERIFIED`인 재료는 모두 "알레르기 확인 필요"다. 검증 전 초안에 적힌 알레르기는 경고에는 쓴다(더 많이 경고하는 쪽은 안전하다). 알레르기가 없는 재료를 확인했으면 `allergens`를 빈 배열로 두고 `verifiedBy`를 채운다.
- **알레르기 재료가 있는 레시피를 열었을 때** [확정: 경고만]
  ```
  레시피 열기 → 경고 화면 "새우가 들어 있어요 (갑각류)" [확인해야 진행]
    → [다른 요리 보기] / [그대로 진행]
  그대로 진행 시: 변경 사항 화면과 해당 재료가 나오는 조리 단계마다 경고 유지
  ```
- 알레르기 재료를 자동으로 대체하거나 대체안을 제시하지 않는다.
- 숨은 성분(간장 속 밀 등)도 같은 방식으로 경고한다.

| `HUMAN_VERIFIED` | 사람이 근거를 보고 확인 | 확인된 매핑 | 필수 |
| `AI_RESEARCHED` | AI가 공개 자료(식약처 알레르기 표시 대상 19종, 일반 시판 제품 원료)로 조사. 헷갈리면 포함 | 확인된 매핑 + "자료 기반" 안내 | 사람 확인으로 승격 필요 |
| 없음 | 초안 또는 사전에 없음 | "확인 필요" → 알레르기 사용자에게 숨김 | 노출 불가 |

- `productVaries: true`(간장·고추장·카레·햄 등 제품마다 성분이 다른 가공 재료): 경고·배지 옆에 "제품마다 달라요. 성분표를 확인하세요". 표시 위치: 레시피 재료 목록, 알레르기 경고 화면, 맞춤 결과(재료 줄과 상단 알레르기 박스), 조리 단계의 알레르기 경고 띠. 알레르기를 고르지 않은 사용자에게는 표시하지 않는다.
- 알레르기 항목 표시 이름: 식약처 표기에 맞춰 '난류' → **'알류'** 로 바꾼다(코드 `egg`는 그대로).
- 등급을 정하는 법(서버): `data/seed/allergen-mapping.json`에서 `verifiedBy`에 확인한 사람 이름이 있으면 `HUMAN_VERIFIED`, 없고 `reviewLevel`이 `AI_RESEARCHED`이면 `AI_RESEARCHED`, 그 밖에는 등급 없음. 파일에 `HUMAN_VERIFIED`라고만 적고 `verifiedBy`가 없으면 인정하지 않는다. 등급은 `ingredient.allergen_review_level`에 저장한다(V6).
- 응답: 레시피 상세의 재료마다 `allergenReviewLevel: 'HUMAN_VERIFIED' | 'AI_RESEARCHED' | null`, `allergenProductVaries: boolean`을 돌려준다. `allergyCheckNeeded`는 등급이 없을 때 `true`다.
- "자료 기반" 안내는 알레르기를 하나 이상 고른 사용자가 `AI_RESEARCHED` 재료가 든 레시피를 열었을 때(레시피 화면, 경고 화면) 표시한다.
- 1차 데이터: `allergen-research-2026-10-09.json`(재료 124개)을 반영했다. 기존 초안에 있던 알레르기는 조사 결과에 없어도 빼지 않았다(식용유의 대두).
- 조사로 사전에 새로 들어온 재료는 분류와 민감도를 정하지 않았다(`category: null`, `HIGH`). 계량은 사전에 없는 재료와 똑같이 다룬다.

### 검색 결과 노출 규칙 [확정 2026-10-09]

| 사용자 | 레시피 재료 상태 | 목록 | 레시피를 열면 |
| --- | --- | --- | --- |
| 알레르기 있음 | 알레르기 해당 재료 있음 | 숨김 | 경고 화면 (해당 재료·알레르기 항목) |
| 알레르기 있음 | 확인 안 된 재료 있음 (해당은 없음) | 숨김 | 경고 화면 ("확인되지 않은 재료가 있어요" + 재료 목록) |
| 알레르기 있음 | 모두 확인됨, 해당 없음 | 표시 | 경고 없음 |
| 알레르기 없음 | 상관없음 | 표시 | 경고 없음, 알레르기 배지 없음 |

- 숨긴 레시피는 목록 아래 한 줄로 알린다: "알레르기 재료가 든 레시피 2개 · 확인 안 된 레시피 3개 · 보기". 두 숫자를 나눠 보여준다.
- "보기"를 누르면 숨긴 레시피가 배지(알레르기 / 알레르기 확인 필요)와 함께 나타난다.
- 경고 화면의 선택지는 기존과 같다: '다른 요리 보기' / '그대로 진행'. 재료를 자동으로 바꾸지 않는다.
- 검색 결과가 전부 숨겨진 경우: 빈 화면 대신 "조건에 맞는 레시피가 숨겨졌어요" + "보기" 버튼.
- 이유: 매핑이 검증되지 않은 재료는 알레르기 성분이 있는지 알 수 없으므로, 알레르기 사용자에게는 해당 재료와 같은 수준으로 조심한다. 검증이 늘어날수록 숨겨지는 레시피가 줄어든다(`docs/release-roadmap.md` P1-08).
- 구현: 서버의 검색 응답은 레시피마다 `allergenCodes`(해당 판단용)와 `allergyCheckNeeded`(확인 안 됨 판단용)를 따로 돌려주고, 숨김 사유는 앱이 기기에 저장된 알레르기와 비교해 정한다(`apps/mobile/src/data/allergy-visibility.ts`). 알레르기 값은 검색 요청에 싣지 않는다(§8.3.1). 한 레시피에 해당 재료와 확인 안 된 재료가 함께 있으면 "해당"으로 한 번만 센다.

### 5.3 개인정보 (출시 대비)
- 알레르기는 건강 관련 정보로 취급한다: 별도 동의, 수집 목적 고지, 암호화 저장 [가정], 로그 출력 금지.
- 앱 내 계정 삭제 기능을 제공한다(App Store 심사 요건).
- 개인정보처리방침이 필요하다. 법률 검토는 출시 전에 별도로 받는다.

### 6.2 GPT 사용
- OpenAI API의 Structured Outputs로 §8 스키마를 강제한다.
- 모델: 테스트하는 동안은 작은 모델 하나를 쓴다(`OPENAI_MODEL`). 나중에 단계별(검색·추출 / 문장 다듬기)로 나눈다. [확정 2026-10-09]
- 비용 상한: 서버가 하루 GPT 호출 횟수를 센다(`OPENAI_DAILY_CALL_LIMIT`, 기본 100회, 전체 합계). 넘으면 GPT를 부르지 않는다. 문장 다듬기는 서버 문장 그대로 응답한다. [확정 2026-10-09] 월 비용 상한과 사용자별 제한은 [미정].
- API 키가 없으면 GPT 호출을 건너뛰고 서버 문장으로 응답한다.
- 같은 (레시피 × 실력 × 도구 조합 × 없는 재료) 조건의 결과는 DB에 캐시해 재호출을 줄인다 [가정].

### 6.3 DB에 없는 요리: 웹 검색으로 가져오기 [확정]
의미: GPT가 레시피를 **지어내는 것이 아니라**, 웹에서 실제 레시피를 찾아 그 내용을 구조화하는 것.

```
요리명/재료 → DB 검색 → 없음/부족
  → GPT 웹 검색 (OpenAI 웹 검색 도구) → 후보 페이지 URL
  → 서버가 페이지를 가져옴 → GPT가 '그 페이지의 내용만' 재료·단계로 추출 (+ 근거 문장 위치)
  → 서버 검증: 추출된 재료·수량이 원문에 실제로 있는지 대조
  → Recipe 저장 (source: WEB_SEARCH, sourceUrl, verificationStatus: IMPORTED)
  → 이후 흐름은 제공 레시피와 동일 (계량 변환, 안전, 알레르기)
```

규칙:
- **MUST NOT** 페이지에 없는 재료·수량·시간을 채워 넣는다. 추출 실패 시 다른 후보를 쓰거나 "찾지 못했어요"로 안내한다.
- UI에 "웹에서 가져온 레시피" 배지와 원문 링크를 표시한다.
- 원문 문장·사진을 그대로 저장하거나 보여주지 않는다. 재료 목록(사실 정보)과 앱 형식으로 다시 쓴 단계만 저장한다. 사진은 앱 그림으로 대체한다. [가정] 출시 전에 저작권·이용약관 검토가 필요하다(법률 자문 아님).
- 같은 요리는 한 번 가져온 결과를 재사용한다(비용 절감).
- [확정] 후보가 여럿이면 **사용자가 가진 도구로 만들 수 있는 레시피를 우선**한다. 예: 오븐이 없는 사용자에게는 같은 요리라도 프라이팬 레시피를 먼저 고른다. 조건에 맞는 후보가 없을 때만 다른 레시피를 가져오고 `requiredItems`로 안내한다.
- [가정 2026-10-09, 검증 전] 원문이 도구를 적지 않은 단계는 행동 종류로 필요한 도구를 채운다(`data/seed/action-tools.json`). 썰기 → 칼, 팬 달구기·볶기·끓이기·굽기 → 프라이팬·냄비·뚝배기 중 하나 + 가스레인지 또는 인덕션. 그 단계가 에어프라이어·오븐·전자레인지·전기밥솥을 쓰면 적용하지 않는다. 없으면 `requiredItems`로 안내한다(몰래 무시하지 않는다).
- 재료 사전이 늘어나면 서버 시작 때 이미 저장된 레시피의 재료를 이름·별칭이 정확히 같은 것만 다시 연결한다. 이전에 "확인 필요"였던 재료에 알레르기·안전 문구가 붙는다.
- 원문에 양이 없는 재료는 "레시피에 양이 적혀 있지 않아요"로 표시한다(`NEEDS_CHECK`).
- 단계 문장은 다시 쓴 것만 저장한다. 원문 문장을 그대로 옮긴 추출(공백 뺀 12자 이상 일치)은 탈락시킨다. 문장 안의 숫자는 원문에 있는 크기·횟수만 허용하고, 양·시간·온도는 문장에 넣지 않는다(변환된 양과 어긋나지 않게).
- [확정 2026-10-09, Q-B4] 출처는 **만개의레시피(`10000recipe.com`)를 우선**한다. 검색할 때 그 사이트부터 찾고, 후보 순서는 ① 가진 도구로 만들 수 있는 것 ② 우선 사이트 순이다. 그 사이트에 맞는 페이지가 없거나 원문 대조에서 탈락하면 다른 사이트를 쓴다. 목록은 `PREFERRED_RECIPE_SITES` 설정. 제외할 사이트는 [미정].

### 6.4 콘텐츠 원천 정리
- COOKRCP01: 식약처의 건강·저염 레시피 위주. 기본 DB로 쓴다.
- 자취 요리(김치볶음밥 등) 같은 부족분은 웹 검색으로 채운다.

### 6.5 재료 기반 추천 [확정 방향]
- 입력: 가진 재료 목록(검색·선택 방식, 자유 입력 시 재료 사전으로 정규화: 파/대파/쪽파 구분).
- 점수 [가정]: 필수 재료 보유율이 높을수록 + 없는 재료가 생략·대체 가능할수록 + 사용자 도구로 가능할수록 높게 한다. 알레르기 레시피는 제외한다.
- DB 결과가 적으면(예: 3개 미만) 웹 검색으로 보충한다.
- 결과 카드에 "없는 재료 N개" 표시.

### 6.6 검증 범위의 현실
요리를 열어 두면 대부분의 레시피는 `IMPORTED`(검증 전) 상태다. 따라서 앱 신뢰성은 **레시피별 검증이 아닌 공통 기준 데이터**(도구 용량, 담기 기준, 무게 기준, 민감도, 안전 규칙, 알레르기 매핑)의 정확도에 달려 있다.
레시피별 생략·대체 규칙은 검증된 레시피에만 적용한다. 그 외 레시피에서 없는 재료는 [가정] 범용 규칙(예: 장식용 깨·파는 생략 가능)이 있을 때만 생략하고, 나머지는 `REQUIRED`로 처리한다.

### 6.7 재료 질문하기 [확정 방향]
조리 화면의 재료 옆에서 자유롭게 질문하는 입력창. 주 용도는 **포장 기준 환산**이다.

예: 사용자 "돼지고기 500g 한 팩 샀어요" → 앱 "팩의 약 1/5만 쓰세요 (레시피 100g)"

처리 방식 (계산은 코드, GPT는 해석만):
```
질문 문장 → GPT: 구조화 추출 {intent: PACKAGE_RATIO, ingredientId, packageGrams: 500}
          → 서버: 100 / 500 = 0.2 → 사람이 이해하기 쉬운 분수로 표현(1/5, 1/4, 1/3, 1/2 …)
          → 답변 템플릿에 채워 반환
```
규칙:
- 레시피 수량은 바꾸지 않는다. 답은 원래 g 기준의 환산만 한다.
- `HIGH` 민감 재료는 분수를 작은 쪽으로 반올림하고 맛보기 안내를 붙인다.
- 지원하지 않는 질문(재료 추가, 레시피 변경, 의학적 질문 등)은 "이 질문에는 답할 수 없어요"로 응답한다. 재료 추가 금지 원칙은 그대로다.
- [가정] 1차 지원 intent: `PACKAGE_RATIO`(포장 비율), `COUNT_TO_AMOUNT`(예: "양파가 큰 거 하나뿐이에요" → `WeightReference` 있을 때만). 이후 확장.
- 질문·답변은 해당 재구성 결과에 기록한다(품질 개선용). 개인정보는 넣지 않는다.

| 항목 | 규칙 |
| --- | --- |
| 양 | 도구 그림 + 담기 기준 그림 + 횟수 + 글. 근사값 안내 |
| 행동 | 한 단계 한 행동 |
| 불 세기 | 불 세기 그림 + 글자 |

| 주의사항 | 해당 단계 카드에 경고 스타일로, 조리 전 요약에도 표시 |
| 변경 사항 | 생략·대체·도구 변경을 조리 전에 표시 |

### 불 세기 표현 [확정: 그림 중심, 5단계]
사용자는 그림을 보고 따라 한다. 그래서 그림이 주 표시다.
- 데이터는 5단계로 저장한다: `LOW`(약불), `MEDIUM_LOW`(중약불), `MEDIUM`(중불), `MEDIUM_HIGH`(중강불), `HIGH`(강불). 원문(`heatRaw`)도 보존.
- [확정] 그림도 5단계를 만든다.
  - 가스: 불꽃 높이·개수가 단계별로 커지는 그림 5장 (`heat.gas.{level}`)
  - 인덕션: 화구 위 열 표시가 단계별로 커지는 그림 5장 (`heat.induction.{level}`). 기기 숫자는 넣지 않는다.
- 그림 아래에 글자("중약불")를 항상 표시한다.
- 그림과 글자는 항상 같은 단계여야 한다. 그림이 없는 단계 값이 오면 검증 실패로 처리한다.
- 5단계 그림 간 차이가 눈으로 구분되는지 사용성 테스트에서 확인한다.

### 오븐·에어프라이어·전자레인지 설정 [확정 2026-10-09]
- 이 기기들은 불 세기 5단계를 쓰지 않는다. 불 세기 그림도 표시하지 않는다.
- 레시피 원문의 설정을 **텍스트 그대로** 보여준다(`device_setting_raw`): "180°C 예열", "200°C", "700W".
- 온도·출력을 다른 값이나 다른 기기 기준으로 **변환하지 않는다.** 기기마다 실제 온도·출력이 달라 변환 결과를 보장할 수 없기 때문이다.
- 표시 방식: 기기 아이콘(`tool.oven` 등) + 설정 텍스트 크게 + "기기마다 조금씩 달라요. 상태를 보며 조절하세요" 안내.
- 시간은 기존 타이머 규칙을 그대로 쓴다. 예열이 있으면 예열은 별도 단계로 나눈다(한 단계 한 행동).
- 오븐·에어프라이어 간 서로 바꾸는 것은 조리법 변경이므로 검증된 규칙이 있을 때만 적용한다("도구 대체·조리법 변경" 항목).

  details?: string;

### 8.3.1 1차(로그인 없음) 계약 [가정]

1차에는 계정과 프로필이 없다. 그래서 §8.2·§8.3과 아래가 다르다. 2차에서 로그인이 들어오면 `profile`은 서버 프로필로 대체한다.

- **재구성 요청에 사용자 조건을 함께 보낸다.**
  ```ts
  type AdaptationRequest = {
    recipeId: string;
    servings: number;                 // 레시피의 baseServings와 같아야 함(인분 변경 규칙 없음)
    missingIngredientIds: string[];
    substituteAnswers?: { ingredientId: string; substituteId: string; hasIt: boolean }[];
    profile: {
      skillLevel: 'LOW' | 'MID' | 'HIGH';
      toolVariantIds: string[];
      defaultHeatSource?: 'gas_stove' | 'induction';  // 둘 다 가졌을 때만 의미 있음
      allergenCodes: string[];        // 요청 처리에만 사용. 저장·로그 출력 금지
    };
  };
  ```
- **알레르기 값은 URL에 넣지 않는다.** URL은 접근 로그에 남기 때문이다. `GET /api/recipes?q=`와 `GET /api/recipes/{id}`는 알레르기를 받지 않고, 레시피가 가진 알레르기 코드(`AllergenMapping` 기준, 숨은 성분 포함)를 응답에 싣는다. 목록 기본 제외와 경고 화면은 앱이 기기에 저장된 알레르기와 이 코드를 비교해 처리한다.
  - 검색 결과 항목: `allergenCodes: string[]`, `allergyCheckNeeded: boolean`(사람이 검증한 매핑이 없는 재료가 있음. §5.2)
  - 상세의 재료: `allergens: { code: string; hidden: boolean }[]`, `allergyCheckNeeded: boolean`, `allergenReviewLevel`, `allergenProductVaries` (§5.2 매핑 검토 등급)
- **응답에 추가된 필드**
  - `AdaptationResponse.allergyCheckNeededIngredientIds: string[]`: `AllergenMapping`에 없어 "확인 필요"로 표시할 재료
  - `AdaptedStep.ingredientIds: string[]`: 해당 재료가 나오는 단계마다 알레르기 경고를 유지하기 위함
- `status`가 `COOKABLE`이 아니면 `ingredients`와 `steps`는 빈 배열이다(확정되지 않은 안내를 보여주지 않는다).
- 생략된 재료는 `ingredients`에 넣지 않고 `changes`(`type: 'OMIT'`, `target`: 재료 ID)로만 알린다.
- `visualKeys`는 행동 그림이 준비될 때까지 빈 배열이다.
- `AdaptedStep.details`(실력별 설명)는 GPT 문장 다듬기가 붙인다. GPT를 쓸 수 없거나 검증에서 탈락한 단계는 비어 있다. 실력은 그 밖에 안전 주의의 자세한 설명(`detail`)에 반영된다.
- **웹에서 레시피 가져오기** [확정 2026-10-09]: `GET /api/recipes?q=`는 DB만 찾는다(GPT를 부르지 않는다). 결과가 없을 때 앱이 아래를 부른다.
  ```ts
  // POST /api/recipe-imports
  type RecipeImportRequest = {
    query: string;              // 요리 이름
    toolVariantIds: string[];   // 가진 도구로 만들 수 있는 페이지를 먼저 고르는 데만 쓴다. 알레르기는 받지 않는다
  };
  // POST 응답, GET /api/recipe-imports/{id} 응답 (앱은 끝날 때까지 몇 초마다 다시 조회)
  type RecipeImport = {
    id: string;                 // "IMPORT_0000000000001"
    status: 'PENDING' | 'SEARCHING' | 'EXTRACTING' | 'VERIFYING' | 'DONE' | 'NOT_FOUND' | 'FAILED';
    recipeId: string | null;    // DONE일 때만
  };
  ```
  - 같은 요리 이름으로 이미 끝난(`DONE`) 작업이나 진행 중인 작업이 있으면 새로 만들지 않고 그것을 돌려준다.
  - API 키가 없거나 하루 호출 횟수를 넘으면 `503 { code: 'AI_UNAVAILABLE' }`.
  - 후보는 최대 3개까지 추출해 보고, 처음으로 원문 대조를 통과한 것을 저장한다. 모두 탈락하면 `NOT_FOUND`.
  - 서버는 `http(s)` 공개 주소의 HTML만 가져온다(내부망 주소 차단, 크기·시간 제한).
- `GET /api/recipe-adaptations/{id}`(재조회)와 결과 캐시(`adapted_recipe`)는 GPT 재구성과 함께 제공한다.
- **ID 형식**: 레시피·레시피 재료·단계 ID는 DB의 20자 문자열 ID다(`"RECIPE_0000000000001"`, `"RINGR_00000000000003"`. 규칙은 `docs/db-setup.md` §6). 도구·알레르기·재료 사전은 DB의 `code`를 쓴다(도구 `teaspoon`, `paper_cup_small`; 알레르기 `egg`, `soybean`). `substituteId`는 대체 재료의 사전 `code`다.
- `display.count`는 분수를 포함한 횟수다(1.5 = 1번 반, 0.5 = 반). `display.fillLevelKey`는 숟가락이면 보여줄 담기 그림(분수가 있으면 그 분수: `liquid.1_2`, 없으면 `liquid.full`·`powder.full`), 컵·그릇·병이면 `null`이다(§4.7).
- 무게로 적힌 재료의 `display.text`는 요청의 `skillLevel`에 따라 달라진다(`LOW`: "밥공기로 가득 1번 (200g)", 그 외: "200g").
- `original.rawText`는 재료 이름을 뺀 양 표현이다(`"1큰술"`). DB에는 이름을 포함한 원문(`"간장 1큰술"`)을 보존한다.

### 8.4 서버 검증 체크리스트 (GPT 응답 후)
1. 스키마가 일치하는가
2. 모든 ID와 그림 키가 존재하는가
3. 사용 도구가 보유 도구 또는 적용된 대체 규칙 안에 있는가
4. 계량값이 서버 계산값과 같은가
5. 원문에 없는 시간이 생기지 않았는가
6. 규칙에 없는 변경이 없는가
7. `SafetyRule`의 트리거에 해당하는 단계에 안전 문구가 빠지지 않았는가
8. 실패 시 1회 재요청 [가정] → 그래도 실패하면 에러 반환, 입력 보존

## 9. 타이머 명세 [확정]

상태: `idle → running ⇄ paused`, `running →(0초) finished`, `running/paused/finished → restart → running`, `running/paused → cancel → cancelled → idle`

```ts
type TimerState = {
  recipeKey: string; stepId: string;
  status: 'idle' | 'running' | 'paused' | 'finished' | 'cancelled';
  durationSeconds: number;
  endAt: number | null;            // epoch ms
  remainingOnPause: number | null; // 초
  notificationId: string | null;
};
```
- 남은 시간은 `max(0, endAt - now)`로 계산한다. interval은 표시용이다.
- start/resume/restart: 기존 알림 취소 → 새 endAt → 알림 예약
- pause/cancel: 알림 취소
- 재진입 시 상태를 복원한다. 시간이 지났으면 `finished`로 두고 재예약하지 않는다.
- 알림 권한을 거부해도 화면 타이머는 동작한다.
- 활성 타이머는 1개, 교체 시 확인한다. 카드·스크롤 보기는 상태를 공유한다. 종료 후 자동 이동하지 않는다.

## 13. 수용 기준

**계량**
- [ ] `설탕 2g(1/3작은술)` → 괄호 값을 기준으로 환산, 원문 보존
- [ ] 1.3숟가락의 `HIGH` 재료 → 1숟가락 + 맛보고 추가 안내
- [ ] `소금 약간` → `NEEDS_CHECK`
- [ ] `돼지고기 100g` (괄호 없음) → 숟가락·컵으로 변환 안 함. 무게 기준이 있고 실력이 `LOW`일 때만 그 기준 도구로 표현 + (g)
- [ ] `1큰술` → 밥숟가락 기준, `1작은술` → 티스푼 기준. 티스푼이 없으면 `1작은술` → "밥숟가락 반"
- [ ] 물 `400ml` → "종이컵 2컵". 고체의 `1컵`은 컵으로 바꾸지 않음
- [ ] `김치 200g` → `LOW`: "밥공기로 가득 1번 (200g)", `MID`·`HIGH`: "200g". 밥공기 3/4처럼 "가득"·"반" 사이의 양은 변환하지 않음
- [ ] 재료 문자열의 소제목("양념장")이 재료로 잘못 파싱되지 않음
- [ ] MANUAL 끝의 잡문자(a/b/c) 제거

**웹 검색·추천**
- [ ] 웹에서 가져온 레시피의 모든 재료·수량이 원문 페이지에 실제로 존재
- [ ] 추출 실패 시 지어내지 않고 "찾지 못했어요" 또는 다음 후보
- [ ] 웹 레시피에 배지와 원문 링크 표시
- [ ] 같은 요리 재요청 시 웹 검색 재호출 없음
- [ ] "파"와 "대파"가 재료 사전으로 올바르게 정규화
- [ ] 추천 결과에 알레르기 레시피 없음

**도구**
- [ ] 칼이 없고 가위만 있음 + 규칙 있음 → `TOOL_SUBSTITUTE` 표시
- [ ] 화구 없음, 전자레인지만 있음 + 규칙 없음 → `NOT_COOKABLE`, `requiredItems`에 화구

**안전·알레르기**
- [ ] 알레르기 해당 레시피가 검색 결과에서 기본 제외
- [ ] 숨은 성분(간장→대두·밀) 감지
- [ ] 직접 연 알레르기 레시피에서 경고 확인 전 진행 불가
- [ ] 경고 화면에서 '다른 요리 보기'/'그대로 진행'만 제공, 자동 대체 없음
- [ ] 그대로 진행 시 해당 재료가 나오는 단계마다 경고 표시
- [ ] `HIGH` 실력에서도 안전 문구 표시
- [ ] 알레르기 값이 서버 로그에 출력되지 않음

**알레르기 매핑 등급**
- [ ] AI_RESEARCHED 재료만 있는 레시피는 알레르기 사용자에게도 숨겨지지 않음(해당 알레르기가 없을 때)
- [ ] 그런 레시피를 열면 "자료 기반이에요. 성분표를 확인하세요" 표시
- [ ] 간장 → 대두·밀(숨은 성분, 제품마다 다름) 경고 표시
- [ ] 김치 → 새우 경고 (새우 알레르기 사용자)
- [ ] 사전에 없는 재료 → 여전히 "확인 필요"로 숨김
- [ ] '파'가 대파로 매칭됨

**알레르기 노출**
- [ ] 알레르기 있음 + 확인 안 된 재료 포함 레시피 → 목록에서 숨김, "확인 안 된 레시피 N개 · 보기" 표시
- [ ] 알레르기 있음 + 해당 재료 포함 → 숨김, "알레르기 재료가 든 레시피 N개" 따로 집계
- [ ] 알레르기 있음 + 모두 확인됨·해당 없음 → 표시, 경고 없음
- [ ] 알레르기 없음 → 숨기는 레시피 0개, 경고 화면·알레르기 배지 0회
- [ ] 검색 결과가 전부 숨겨지면 빈 화면이 아니라 안내 + "보기"

**재구성·GPT**
- [ ] 필수 재료 + 규칙 없음 → `NOT_COOKABLE`
- [ ] 대체안 → `NEEDS_CONFIRMATION` → 응답 반영
- [ ] 잘못된 JSON, 없는 그림 키, 미보유 도구 → 검증 실패
- [ ] GPT 실패·타임아웃 시 입력 보존 + 재시도

**계정**
- [ ] 비밀번호 재설정 토큰은 1회용, 만료 시간 있음, DB에는 해시로 저장
- [ ] 게스트가 가입하면 기기에 있던 실력·도구가 프로필로 옮겨짐
- [ ] 게스트가 재구성 1회 후 새 요리 시작 시 가입 안내, 이미 받은 결과는 다시 열 수 있음
- [ ] 아이디·닉네임·이메일 중복 가입 불가
- [ ] 아이디 `ab1`(3자), `Abcd`(대문자) 거절 / 비밀번호 `abcdefgh`(숫자 없음) 거절
- [ ] 아이디 찾기·비밀번호 찾기 화면 문구로 가입 여부가 드러나지 않음
- [ ] 게스트 알레르기 정보가 서버에 저장되지 않음
- [ ] 재로그인 시 실력·도구·알레르기 유지
- [ ] 계정 삭제 시 프로필·알레르기 정보 삭제

**도구 추가분**
- [ ] 계량스푼 보유 → "간장 1큰술" 그대로 표시, '대략적인 기준' 배지 없음
- [ ] 계량스푼만 보유 → 큰술·작은술은 원래대로, 컵 단위는 기존 변환
- [ ] 오븐 단계 → 불 세기 그림 없이 "180°C 예열" 텍스트 그대로, 값 변환 없음
- [ ] 예열이 있으면 별도 단계로 분리
- [ ] 채칼·강판·오븐·찜기·뚝배기 사용 단계에 안전 문구 표시 (실력 수준 무관)
- [ ] 같은 요리 후보 중 사용자 도구로 가능한 레시피가 우선 선택됨
- [ ] '처음 해봐요'는 '더 있어요'가 접힌 상태, '요리에 익숙해요'는 펼친 상태

**타이머·불 세기**
- [ ] "3분" → 180초, 시작 기준 보존
- [ ] 각 조작 후 예약 알림 0개 또는 1개
- [ ] 잠금·백그라운드·재실행 후 복원 (iPhone development build)
- [ ] 알림 권한 거부 시에도 화면 타이머 동작
- [ ] 자동 단계 이동 없음, 교체 확인
- [ ] "중약불" → `MEDIUM_LOW`, 중약불 그림 + "중약불" 글자 (그림·글자 단계 일치)

**재료 질문하기**
- [ ] "돼지고기 500g 팩" (레시피 100g) → "약 1/5", 계산은 서버에서
- [ ] 레시피 수량 자체는 변경되지 않음
- [ ] 재료 추가·레시피 변경 질문 → 답변 거절

**기준값 출처**
- [ ] `ASSUMED` 기준으로 변환된 양에 '대략적인 기준' 안내 표시
- [ ] 검증되지 않은 담기 기준 그림은 쓰지 않고 글자로만 안내 (분수 표현 자체는 사용)
- [ ] 소복이(heaped)는 계산에 쓰지 않음
